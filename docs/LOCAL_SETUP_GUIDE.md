## 4. Required Clerk Setup

Clerk provides authentication (login, signup, session management). You need a Clerk account.

### Step 4.1: Create a Clerk Application

1. Go to https://dashboard.clerk.com
2. Click **"Add application"**
3. Choose a name (e.g., "SymptomScope AI")
4. Select **"Email + Google"** or any providers you want
5. Click **"Create application"**

### Step 4.2: Get API Keys

From the Clerk dashboard homepage:

| Key | Location | Required For |
|-----|----------|-------------|
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | API Keys page (frontend) | Frontend |
| `CLERK_SECRET_KEY` | API Keys page (backend/API) | Frontend |
| `CLERK_JWKS_URL` | Under "Advanced" → "JWKS URL" | Backend |

The JWKS URL format is:
```
https://<your-instance>.clerk.accounts.dev/.well-known/jwks.json
```

Alternatively, you can use the Issuer URL:
```
https://<your-instance>.clerk.accounts.dev
```

### Step 4.3: Configure Clerk URLs

In the Clerk Dashboard → **Sessions** → **Redirect URLs**, add:
```
http://localhost:3000
http://localhost:3000/sso-callback
```

In Clerk Dashboard → **User & Authentication** → **Email, Phone, Username**, configure sign-in methods as desired. The default (Email + Google) works out of the box.

## 5. Required Environment Variables

### Backend `.env`

Create from template:

```powershell
# PowerShell
Copy-Item -LiteralPath "backend/.env.example" -Destination "backend/.env"
```

**Required variables** (must be set):

```env
# MongoDB connection URI
MONGODB_URI=mongodb://localhost:27017/symptomscope

# Allowed CORS origins (comma-separated)
CORS_ORIGINS=http://localhost:3000

# Clerk authentication (at least ONE of these)
CLERK_JWKS_URL=https://your-instance.clerk.accounts.dev/.well-known/jwks.json
```

**Optional variables** (safe defaults provided):

```env
MONGODB_MAX_POOL_SIZE=10
MONGODB_MIN_POOL_SIZE=2
SENTRY_DSN=
SENTRY_ENV=development
SENTRY_TRACES_SAMPLE_RATE=0.1
LOG_LEVEL=INFO
LOG_FORMAT=json
REDIS_URL=
DEBUG=false
APP_NAME=SymptomScope AI
APP_VERSION=1.0.0
```

> **Note on `CLERK_JWKS_URL` vs `CLERK_ISSUER`:** You only need one. If you set `CLERK_JWKS_URL`, the JWKS endpoint is used directly. If you set `CLERK_ISSUER`, the backend appends `/.well-known/jwks.json` automatically. If both are empty, **authentication will fail** with a 500 error.

### Frontend `.env.local`

Create from template:

```powershell
# PowerShell
Copy-Item -LiteralPath "frontend/.env.example" -Destination "frontend/.env.local"
```

**Required variables:**

```env
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_xxxxxxxxxxxxxxxxxxxx
CLERK_SECRET_KEY=sk_test_xxxxxxxxxxxxxxxxxxxx
NEXT_PUBLIC_API_URL=http://localhost:8000
```

**Optional variables** (leave as-is if not using):

```env
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/login
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/signup
NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL=/dashboard
NEXT_PUBLIC_CLERK_AFTER_SIGN_UP_URL=/dashboard
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
NEXT_PUBLIC_SENTRY_DSN=
SENTRY_DSN=
NEXT_PUBLIC_POSTHOG_KEY=
NEXT_PUBLIC_POSTHOG_HOST=https://us.i.posthog.com
```

> If Clerk keys are missing/invalid, the frontend will fail to load login/signup pages and redirects will loop. PostHog and Sentry keys can be left blank — those services are gracefully disabled at runtime.

## 6. Required MongoDB Setup

MongoDB can run either via Docker (recommended) or a local installation.

### Option A: Docker Container (Recommended)

```powershell
# Pull and run MongoDB 7
docker run -d `
  --name symptomscope-mongo `
  -p 27017:27017 `
  -v mongodb_data:/data/db `
  mongo:7
```

Verify it is running:

```powershell
docker ps --filter "name=symptomscope-mongo"
```

The connection string `mongodb://localhost:27017/symptomscope` in `.env` will work automatically.

### Option B: Local MongoDB Installation

Download from https://www.mongodb.com/try/download/community and install, then:

```powershell
# Start MongoDB service
net start MongoDB

# Or if installed manually:
& "C:\Program Files\MongoDB\Server\7.0\bin\mongod.exe" --dbpath "C:\data\db"
```

### Database Initialization

The backend creates the database and collections **automatically on first startup**:

| Collection | Indexed Fields | Purpose |
|------------|---------------|---------|
| `predictions` | `userId`, `userId + timestamp`, `timestamp` | Stores prediction records |

No manual database creation is needed. The backend calls `ensure_indexes()` during its lifespan startup (`main.py:30`) which creates the required indexes.

## 7. Docker Setup (The Exact Steps)

This is the recommended method. It runs three containers: MongoDB, the Python backend, and the Next.js frontend.

### Step 7.1: Create Environment Files (if not done)

```powershell
Copy-Item -LiteralPath "backend/.env.example" -Destination "backend/.env"
Copy-Item -LiteralPath "frontend/.env.example" -Destination "frontend/.env.local"
```

### Step 7.2: Edit Environment Files

**`backend/.env`** - Set these minimum values:

```env
MONGODB_URI=mongodb://mongodb:27017/symptomscope
CORS_ORIGINS=http://localhost:3000
CLERK_JWKS_URL=https://<your-instance>.clerk.accounts.dev/.well-known/jwks.json
```

> **Important:** When using Docker, `MONGODB_URI` must use `mongodb` (the Docker service name) as the host, not `localhost`. The `docker-compose.yml` line 27 overrides this automatically:
> ```yaml
> environment:
>   - MONGODB_URI=mongodb://mongodb:27017/symptomscope
> ```
> If you want to set it manually in `.env`, make sure it matches.

**`frontend/.env.local`** - Set these minimum values:

```env
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_xxxxxxxxxxxxxxxxxxxx
CLERK_SECRET_KEY=sk_test_xxxxxxxxxxxxxxxxxxxx
NEXT_PUBLIC_API_URL=http://localhost:8000
```

### Step 7.3: Start All Containers

```powershell
docker-compose up --build
```

This command:
1. Builds the `backend` Docker image from `backend/Dockerfile` (Python 3.13-slim, installs all pip dependencies)
2. Builds the `frontend` Docker image from `frontend/Dockerfile` (Node.js 22-alpine, multi-stage build)
3. Pulls `mongo:7` image for the database
4. Starts all three containers in order (MongoDB → backend → frontend)
5. Mounts the Docker volume `mongodb_data` for persistent storage

### Step 7.4: Wait for Startup

Monitor the logs:

```powershell
# Follow all containers
docker-compose logs -f

# Or just the backend
docker-compose logs -f backend

# Or just the frontend
docker-compose logs -f frontend
```

Expected backend startup log sequence:
1. `[INFO] Sentry disabled: no DSN configured` (if no SENTRY_DSN)
2. `[INFO] Environment: ...`
3. `[INFO] Application startup complete`

### Step 7.5: Access the Application

| Service | URL |
|---------|-----|
| Frontend | http://localhost:3000 |
| Backend API | http://localhost:8000 |
| API Docs (Swagger) | http://localhost:8000/docs |
| API Docs (ReDoc) | http://localhost:8000/redoc |
| Health Check | http://localhost:8000/health |

### Step 7.6: Stopping Containers

```powershell
# Stop and remove containers
docker-compose down

# Stop, remove, and delete MongoDB data volume
docker-compose down -v

# Stop only (preserve containers)
docker-compose stop
```

### Step 7.7: Rebuilding After Changes

```powershell
# Rebuild both backend and frontend images
docker-compose up --build

# Rebuild only the backend
docker-compose up --build backend

# Rebuild only the frontend
docker-compose up --build frontend
```

## 8. Manual Setup (No Docker)

Use this if you don't have Docker or prefer running processes locally.

### Step 8.1: Start MongoDB

```powershell
# Option A: Docker (even without Docker Compose)
docker run -d -p 27017:27017 mongo:7

# Option B: Local install
# (install MongoDB Community Server first)
net start MongoDB
```

### Step 8.2: Backend Setup

```powershell
cd backend

# Create Python virtual environment
python -m venv venv

# Activate it
.\venv\Scripts\Activate.ps1   # Windows PowerShell
# source venv/bin/activate    # macOS / Linux

# Install dependencies
pip install -r requirements.txt

# Create environment file (if not done)
Copy-Item -LiteralPath ".env.example" -Destination ".env"
# Edit .env with your values (see section 5)

# Start the backend server
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Expected output:
```
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

### Step 8.3: Frontend Setup (in a new terminal)

```powershell
cd frontend

# Install dependencies
npm ci

# Create environment file (if not done)
Copy-Item -LiteralPath ".env.example" -Destination ".env.local"
# Edit .env.local with your values (see section 5)

# Start the development server
npm run dev
```

Expected output:
```
> frontend@0.1.0 dev
> next dev

  ▲ Next.js 16.2.9
  - Local: http://localhost:3000
```

> **Note:** Use `npm ci` (not `npm install`). The project uses lockfile-based installs. If `npm ci` fails, delete `node_modules` and try again, or use `npm install --legacy-peer-deps` as a fallback.

## 10. Common Startup Errors

### Error: `MongoDB connection refused`

```
pymongo.errors.ServerSelectionTimeoutError: localhost:27017: [Errno 111] Connection refused
```

**Fix:** Ensure MongoDB is running:
```powershell
docker ps --filter "name=mongo"
# If not running:
docker run -d -p 27017:27017 mongo:7
```

### Error: `Clerk: Missing Clerk JWKS URL`

```
RuntimeError: JWKS configuration missing
```

**Fix:** Set `CLERK_JWKS_URL` or `CLERK_ISSUER` in `backend/.env`:
```env
CLERK_JWKS_URL=https://your-instance.clerk.accounts.dev/.well-known/jwks.json
```

### Error: `Clerk: Publishable Key not found`

```
[vite] ClerksJS: publishableKey is missing. Pass it as a prop to <ClerkProvider>
```

**Fix:** Set `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` in `frontend/.env.local`.

### Error: `Module not found: Can't resolve '...'`

```
Module not found: Can't resolve 'some-module'
```

**Fix:** Reinstall frontend dependencies:
```powershell
cd frontend
Remove-Item -Recurse -Force node_modules
npm ci
```

### Error: `Port already in use` (EADDRINUSE)

```
Error: listen EADDRINUSE: address already in use :::8000
```

**Fix:** Kill the process using the port, or change ports:
```powershell
# Find what's using port 8000
netstat -ano | findstr :8000

# Kill the process (replace PID with actual number)
taskkill /PID 12345 /F
```

### Error: `docker-compose: command not found`

**Fix:** Install Docker Desktop from https://www.docker.com/products/docker-desktop/

### Error: `npm ci` fails with dependency conflicts

```
npm ERR! code ERESOLVE
npm ERR! Could not resolve dependency
```

**Fix:** Use the legacy peer deps flag:
```powershell
npm ci --legacy-peer-deps
```

### Error: `pip install` fails to install `shap` (no C++ compiler)

```
error: Microsoft Visual C++ 14.0 or greater is required.
```

**Fix:** Install Visual C++ build tools from:
https://visualstudio.microsoft.com/visual-cpp-build-tools/

Or use a pre-built wheel:
```powershell
pip install shap --only-binary=shap
```

### Error: `curl` is not recognized

**Fix:** Use PowerShell's `Invoke-RestMethod` instead:
```powershell
Invoke-RestMethod -Uri "http://localhost:8000/health"
```

Or install curl from https://curl.se/windows/

### Error: Docker MongoDB fails to start (port conflict)

```
Error starting userland proxy: listen tcp4 0.0.0.0:27017: bind: address already in use
```

**Fix:** MongoDB is already running locally. Either stop the local MongoDB service (`net stop MongoDB`) or use the manual setup instead of Docker.
